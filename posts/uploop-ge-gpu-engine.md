# Uploop GE GPU Engine

Uploop GE is a GPU engine designed for the browser. It wraps WebGPU with higher-level abstractions for rendering, compute, and streaming data. GE is not a game engine — it's a rendering and compute framework for data visualization, 3D UI, and AI-powered graphics.

## Architecture

```
Application
    │
┌───▼────────────────────┐
│   Uploop GE              │
│  ┌────────────────────┐ │
│  │ Scene Graph        │ │
│  │ (transforms, LODs) │ │
│  ├────────────────────┤ │
│  │ Render Graph       │ │
│  │ (passes, barriers) │ │
│  ├────────────────────┤ │
│  │ Compute Graph      │ │
│  │ (shaders, buffers) │ │
│  └────────────────────┘ │
│           │             │
│  ┌────────▼──────────┐ │
│  │  WebGPU Adapter   │ │
│  └───────────────────┘ │
└─────────────────────────┘
```

Three layers: scene graph (what to render), render graph (how to render), compute graph (GPU computation). The scene graph is declarative — you describe the scene and GE generates the render graph automatically. The compute graph is for custom GPU work (particles, physics, ML inference).

## Scene Graph

```typescript
import { Scene, Mesh, Light, Camera, Material } from '@uploop/ge';

const scene = new Scene();

const camera = new Camera({
  position: [0, 2, 5],
  fov: 60,
});

const light = new Light({
  type: 'directional',
  direction: [1, -1, 1],
  intensity: 10,
});

const mesh = new Mesh({
  geometry: 'sphere',
  material: new Material({
    baseColor: [1, 0.4, 0],
    roughness: 0.3,
    metalness: 0.1,
  }),
  transform: {
    position: [0, 1, 0],
    scale: [1.5, 1.5, 1.5],
  },
});

scene.add(camera);
scene.add(light);
scene.add(mesh);
```

The scene graph manages spatial indexing (BVH for ray casting, frustum culling for rendering), transforms (hierarchy with dirty propagation), and level-of-detail selection (distance-based mesh LODs). LODs are computed at import time — each mesh has 3-4 LOD levels generated by mesh simplification (Quadric Error Metrics). The scene graph selects the appropriate LOD based on the object's projected screen size.

## Render Graph

The scene graph is compiled to a render graph each frame:

```typescript
const renderGraph = scene.compile(); // Generates render passes

// renderGraph[0]: Shadow map pass (directional light)
// renderGraph[1]: Opaque geometry pass (GBuffer)
// renderGraph[2]: Lighting pass (deferred shading)
// renderGraph[3]: Transparent geometry pass (forward)
// renderGraph[4]: Post-processing (bloom + tonemap)
// renderGraph[5]: UI overlay pass
```

The render graph is GE's internal representation — application code doesn't touch it directly. It's exposed for debugging (render graph visualization in DevTools) and for advanced users who want custom passes:

```typescript
const customPass = new RenderPass({
  shader: myCustomShader,
  inputs: [renderGraph[1].output], // GBuffer
  outputs: [texture],
});
renderGraph.insertAfter(customPass, 3); // Insert after lighting
```

## Compute Graph

```typescript
const computeGraph = new ComputeGraph();

const particles = computeGraph.buffer(10000 * 4 * 4); // 10K particles, Vec4 each
const forces = computeGraph.buffer(10000 * 4);

computeGraph.dispatch('update_particles', {
  workgroups: [40, 1, 1],
  inputs: [particles, forces],
  outputs: [particles],
});

computeGraph.dispatch('render_particles', {
  workgroups: [40, 1, 1],
  inputs: [particles],
  outputs: [drawIndirect],
});
```

Compute graphs can be submitted independently from the render graph. We run particle systems at 120 Hz (separate from the 60 Hz render loop) to get smooth motion. The GPU handles both without CPU intervention — GE's compute graph is double-buffered so the CPU can modify the next frame's input while the GPU processes the current frame.

## Performance

GE targets 60 FPS on integrated GPUs (Intel Iris Xe, Apple M1) and 120+ FPS on discrete GPUs:

| Scene | iGPU (M1) | dGPU (RTX 3060) |
|---|---|---|
| 100 meshes, 1 light | 60 FPS | 144 FPS |
| 1000 meshes, 4 lights | 45 FPS | 120 FPS |
| Particle system (100K) | 55 FPS | 144 FPS |
| Post-processing (bloom) | 50 FPS | 120 FPS |

On integrated GPUs, the bottleneck is fill rate (pixel shader throughput). On discrete GPUs, it's draw call overhead — GE batches draw calls by material to minimize state changes. A 1000-mesh scene with 20 materials produces about 40 draw calls after batching. Without batching (Bevy-style, each mesh = individual draw call), draw calls would be 1000+ and frame time would double on integrated GPUs.
